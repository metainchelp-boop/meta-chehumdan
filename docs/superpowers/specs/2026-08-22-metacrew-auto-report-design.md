# 메타체험단 결과보고서 자동 생성 및 공유 허브 정합성 설계

## 목표

- 캠페인 결과일이 지난 회차의 광고주용 결과보고서를 사람의 추가 조작 없이 생성한다.
- 늦은 리뷰 승인 또는 승인 취소가 생기면 기존 공개 주소를 유지한 채 보고서 내용을 갱신한다.
- 이미 완료됐지만 보고서 파일이 없는 회차를 안전하게 소급 생성한다.
- 메타체험단 원천 API와 공유 허브의 PC·모바일 화면에서 동일한 보고서 목록과 기능을 제공한다.
- 스토어·플레이스 겸용 광고주의 계약·일정·온보딩 중복과 오해를 부르는 상태 문구를 정리한다.

순위추적 수집기·일일 처리 한도·재시도 로직은 이번 범위에서 제외한다.

## 확정 방식

### 보고서 생성 시점

1. 기존 일일 크론이 `cp_result_datetime <= 현재 시각`인 완료 캠페인을 확인한다.
2. 공개 보고서 파일이 없으면 생성한다. 이를 통해 기존 완료 회차도 소급 생성한다.
3. 리뷰가 등록완료로 승인되거나 승인이 취소될 때, 해당 캠페인의 공개 보고서가 이미 있거나 결과일이 지났다면 같은 파일을 다시 생성한다.
4. 공개 주소는 기존 `mc_share_token(cp_id)` 기반 고정 주소를 유지한다. 갱신 시 주소는 바뀌지 않는다.

매 조회마다 생성하는 방식은 사용하지 않는다. 공개 공유 링크와 광고주 집계 API는 계속 읽기 전용이어야 한다.

### 컴포넌트 경계

- `lib/mc_campaign_report.lib.php`
  - 캠페인 한 건의 집계, 개인정보 마스킹, HTML 렌더링, 원자적 파일 교체를 담당한다.
  - 관리자 화면·크론·리뷰 상태 변경은 이 함수만 호출한다.
- `admin/campaign_report_share.php`
  - 관리자 권한 확인과 성공·실패 안내만 담당한다.
  - 실제 보고서 생성은 공용 라이브러리에 위임한다.
- `crontab/campaign.php`
  - 완료 캠페인 중 보고서가 없는 대상을 제한된 건수만 처리한다.
  - 한 건 실패가 다른 캠페인과 기존 크론 작업을 막지 않으며 실패를 크론 로그에 남긴다.
- `lib/campaign.lib.php`
  - `review_confirm`과 `review_post_cancel` 완료 후 보고서 갱신을 요청한다.
  - 보고서 갱신 실패가 리뷰 승인·포인트 처리 자체를 되돌리지는 않는다.
- `mc_advertiser_api.php`
  - 공개 파일이 실제 존재할 때만 `report_public_url`, `report_at`을 반환한다.
  - 기능 브랜치에만 있던 운영 파일을 기본 브랜치에 정식 반영한다.

## 안전 조건

- HTML은 임시 파일에 쓴 뒤 같은 파일시스템에서 원자적으로 교체한다. 생성 중인 반쪽 파일을 광고주에게 노출하지 않는다.
- 보고서 생성 실패는 기존 공개 파일을 삭제하거나 덮어쓰지 않는다.
- 같은 캠페인에는 현재 HMAC 주소 하나만 유지하되, 새 파일 저장이 성공한 후에만 구 토큰 파일을 정리한다.
- 이름은 기존과 동일하게 마스킹하고 연락처·회원 원문·관리자 전용 URL은 공개 HTML과 공개 API에 포함하지 않는다.
- 자동 배치는 한 번에 처리할 최대 건수를 제한해 운영 DB와 파일시스템 부하를 제어한다.
- 수동 `광고주 공유 보고서 만들기` 버튼은 운영상 재생성이 필요할 때를 위해 유지한다.

## 공유 허브 정합성

- 겸용 광고주의 계약은 `상품 코드 + 계약 기간 + 상태`가 같은 경우 한 번만 노출한다.
- 일정은 `상품 코드 + 일정 종류 + 예정일 + 공개 상태`가 같은 경우 한 번만 노출한다.
- 온보딩은 `상품 코드 + 항목 키`가 같은 경우 최신 완료 기록 하나만 노출한다.
- 실제 성과 지표가 0건이면 광고 운영 연결 정보가 있어도 `광고성과 확인 가능`으로 표현하지 않는다.
- 체험단 캠페인 데이터와 보고서 파일 상태는 분리해 판정한다. 캠페인은 있으나 보고서가 없으면 보고서 영역에 명확한 빈 상태를 표시한다.
- PC와 모바일은 같은 응답·같은 항목·같은 링크를 사용한다. 모바일은 카드 순서와 폭만 반응형으로 바꾸며 기능을 숨기지 않는다.

## 실패 처리

- 한 캠페인 생성 실패: 해당 회차 기존 파일 유지, 크론 로그에 캠페인 번호와 실패 사유 기록, 다음 캠페인 계속 처리.
- 트래픽 주차 테이블 없음: 트래픽 값만 0으로 표시하고 나머지 보고서는 생성.
- Chart 라이브러리 없음: 보고서 생성 실패로 기록하고 기존 파일 유지.
- 공개 API에서 파일 없음: 잘못된 URL을 만들지 않고 보고서 필드를 빈 값으로 반환.

## 회귀 검증

1. 결과일 전 캠페인은 자동 생성하지 않는다.
2. 결과일이 지난 파일 없는 캠페인은 배치에서 생성한다.
3. 같은 캠페인을 재생성해도 URL은 동일하고 HTML 내용과 수정 시각만 갱신된다.
4. 리뷰 승인·취소 후 보고서 수치가 갱신되며 리뷰 업무 처리는 보고서 실패와 독립적이다.
5. 파일 쓰기 실패 시 기존 공개 파일이 보존된다.
6. 공개 API는 존재하는 `http/https` 보고서 주소만 반환하고 내부 관리자 주소·토큰 원문을 추가 노출하지 않는다.
7. 겸용 광고주에서 중복 계약·일정·온보딩이 한 번만 노출된다.
8. 실제 성과 지표가 없을 때 광고성과 카드는 빈 상태를 표시한다.
9. 실제 공유 링크를 1280px와 390px에서 열어 체험단 보고서 개수·링크·카드 순서가 동일하고 가로 넘침이 없는지 확인한다.
10. 현재 대상 광고주의 완료 1~3회차가 소급 생성되어 공유 링크에 세 개의 결과보고서로 표시되는지 확인한다.

## 배포 순서

1. 메타체험단 공용 생성기·크론·집계 API를 배포하고 완료 회차를 소급 생성한다.
2. 메타체험단 API에서 실제 보고서 URL을 확인한다.
3. 공유 허브 백엔드의 중복 제거·상태 판정을 배포한다.
4. 공유 허브 프론트의 명시적 보고서 빈 상태와 PC·모바일 동일 노출을 배포한다.
5. 사용자가 제공한 동일 공유 링크로 최종 실측한다.
